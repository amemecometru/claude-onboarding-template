## Pre-delivery verification checklist

- [ ] Confirm product name and current feature terminology.
- [ ] Confirm licensing, user prerequisites, and app/client requirements for the actual tenant.
- [ ] Verify each admin step in current Microsoft Learn documentation; avoid guessing UI labels from memory.
- [ ] Confirm whether named reports, dashboards, controls, or onboarding experiences are available and enabled in the tenant.
- [ ] Confirm who owns tenant configuration, identity, data access, information protection, retention, support, and approvals.
- [ ] Review content permissions and oversharing with authorized client owners; do not imply licensing fixes access.
- [ ] Have client security/privacy/compliance owners decide which controls and obligations apply.
- [ ] Confirm data collection, user feedback, and telemetry handling with the client.
- [ ] Test end-user links, support routes, accessible language, and instructions with a reviewer.
- [ ] Date the review and identify unresolved issues and assumptions.

## Source and attribution rules

- Prefer current Microsoft Learn or Microsoft Adoption pages for Microsoft product behavior.
- Attribute Microsoft’s guidance as Microsoft guidance; identify this repository’s lifecycle, thresholds, templates, and role assignments as proposed working practices unless Microsoft explicitly specifies them.
- Do not describe this portfolio as Microsoft-certified, Deloitte-approved, tenant-validated, or proven at enterprise scale.
- A link is a verification aid, not evidence that a control is configured in a client tenant.
