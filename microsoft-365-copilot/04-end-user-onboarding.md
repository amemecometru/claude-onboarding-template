## A simple way to try an approved task

1. **Name the task.** Say what you need help drafting, summarizing, or organizing.
2. **Give useful context.** Include only approved context and identify the intended audience or format.
3. **State constraints.** Mention what to include, what to avoid, and which approved source to use.
4. **Review the result.** Check facts, names, dates, numbers, citations, tone, completeness, and whether the output followed the request.
5. **Take responsibility.** Correct the draft and follow normal approval procedures before sharing, sending, recording, or acting on it.

Example prompt pattern (replace with an approved, non-sensitive scenario):

> Help me [task] for [audience]. Use [approved source/context]. Return [format]. Do not assume missing facts; list questions or uncertainties. I will review the result before using it.

This pattern is a starting point, not a guarantee of accuracy. Use the instructions and controls approved by your organization.

## Check before relying on an answer

- Is each important claim supported by a source you can open and verify?
- Are dates, amounts, names, calculations, and quotations correct?
- Has anything important been omitted or invented?
- Does the output include information that should not be shared with this audience?
- Does this task need subject-matter, manager, legal, compliance, or other approval?
- Is the next action allowed by policy? Copilot output does not approve or perform the action for you.

If the output is wrong, unsafe, unexpected, or reveals content you should not see, stop using it for that task and report it via [approved help/incident route]. Do not copy sensitive content into an unapproved feedback channel.
